# 數位銀行資訊安全與身份驗證規範

## 文件資訊
- **文件編號**：DIGITAL-SEC-001
- **適用範圍**：數位銀行部、資訊安全部、行動銀行 App 開發團隊
- **最近更新**：2024-06-01
- **主管機關依據**：金管會「金融機構辦理電子銀行業務安全控管作業基準」

---

## 一、身份驗證分級機制

本行依交易金額及風險等級，採用多因子身份驗證（MFA）：

| 交易等級 | 門檻 | 驗證方式 |
|--------|-----|--------|
| 低風險 | 查詢、餘額、≤5,000元轉帳 | 密碼（6位數PIN）|
| 中風險 | 5,001–100,000元 | 密碼 + OTP簡訊 |
| 高風險 | 100,001–500,000元 | 密碼 + OTP + 臉部辨識 |
| 極高風險 | > 500,000元 | 密碼 + OTP + 臉部辨識 + 語音確認 |
| 新受益帳戶首次匯款 | 任何金額 | 密碼 + OTP + 聲音驗證 |

## 二、行動銀行安全規範

### 2.1 設備綁定

- 每個帳戶最多綁定 **3台裝置**
- 更換手機需重新進行生物特徵綁定（臉部辨識）
- 裝置綁定後，未綁定裝置的轉帳功能自動關閉

### 2.2 Session 管理

- 閒置超過 **10分鐘**自動登出
- 每 **30天**強制重新驗證身份（含生物特徵）
- 帳號連續輸錯密碼 **5次**：鎖定24小時，需臨櫃解鎖

### 2.3 交易限額（可由客戶設定，不得超過以下上限）

| 管道 | 每筆上限 | 每日上限 |
|-----|--------|--------|
| App 轉帳（已知帳戶） | 200萬 | 300萬 |
| App 轉帳（新帳戶） | 5萬 | 10萬 |
| ATM 提款 | 5萬/次 | 10萬 |
| 網路ATM | 50萬 | 100萬 |

## 三、資料保護與加密標準

### 3.1 傳輸加密

- 所有 API 通訊採用 **TLS 1.3**（不接受 1.2 以下）
- 敏感資料傳輸使用 **AES-256** 端對端加密
- 憑證效期 ≤ 1年，到期前 30天自動更新

### 3.2 靜態資料加密

- 核心系統資料庫：HSM（硬體安全模組）金鑰管理
- 客戶生物特徵（臉部、聲紋）：儲存於隔離的安全飛地（Secure Enclave）
- 禁止在 App log 或一般資料庫中明文儲存密碼、CVV、完整卡號

### 3.3 個資去識別化

- 用於分析的客戶資料，依金管會「金融資料應用作業指引」進行去識別化
- 測試環境禁止使用正式客戶真實資料

## 四、資安事件分級與應變

| 等級 | 情境描述 | 應變時間 | 通報層級 |
|-----|--------|--------|--------|
| P1 | 核心系統被入侵、大規模資料外洩 | **15分鐘**內啟動 | CEO、金管會、調查局 |
| P2 | 大量帳戶異常登入、DDoS攻擊 | **30分鐘**內啟動 | CTO、資安長 |
| P3 | 單一帳戶遭盜用 | **2小時**內處理 | 資安部 |
| P4 | 系統漏洞揭露（已修復） | **24小時**內評估 | 資訊部 |

### 重大事件通報義務

依金管會規定，**P1/P2 等級事件**須在事件確認後 **1小時內**通報金融監督管理委員會，並在 **24小時內**提交初步調查報告。

## 五、滲透測試與弱點掃描

- **弱點掃描**：每月一次（自動化工具）
- **滲透測試**：每半年委由第三方資安公司執行
- **紅隊演練**：每年一次（包含社交工程測試）
- **Bug Bounty 計劃**：外部白帽駭客回報獎金最高 **50萬元**

所有發現的高危漏洞須在 **30天內**完成修補，中危漏洞須在 **90天內**修補。
